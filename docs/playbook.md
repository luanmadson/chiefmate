# Playbook: improving Chiefmate

The guide for the crew, and for anyone, changing Chiefmate itself. Read it whole before you start.

Chiefmate improves itself: the crew works on a copy of this repository and every change ends in a pull request. When the owner merges it, each installation updates itself within minutes, once its crew is free. That is why the rules below matter: a careless change reaches running installations.

## How the code is organized

| Place | What it holds |
|---|---|
| `src/server.mjs` | The app's web server and API. It listens on this computer only. With `remote_access`, a second listener (also on 127.0.0.1) for Tailscale Serve alone: `remoteSettings` reads the setting, `remoteRefusal` checks the tailnet name, the Origin and the allowed `Tailscale-User-Login`, and `OPENS_ON_PC` lists the commands refused from another device. |
| `src/runs.mjs` | How a run goes: the working copy, the crew in sequence, the review, the checks and the pull request. No step publishes anything: `ALWAYS_DISALLOWED` refuses the commands that start with a publication, and `crewGuard` (also used by the manager's conversation in `src/manager.mjs`) runs the guard of `src/guard.mjs` before each command to refuse the rest, however they are written. Several runs (of different projects) go on at once: what the app shows of each is in `live`, by run id. |
| `src/queue.mjs`, `src/schedule.mjs` | One run per project at a time, runs of different projects side by side up to `max_parallel`; missions on their days and times. |
| `src/sessions.mjs` | The live sessions: the profiles (the settings' own, then an automatic one per project and tool, never saved), the first message from the prompt builder; in the app, the conversation turn by turn (`deliverSession`: Claude Code through `runClaude` with `--resume`, Codex through `codex exec --json` and `codex exec resume`, `codexItem` for its events), the queue, the interruption, the pause of the turns for an update and their carrying on after it (`pauseSessionTurns`, `resumeSessions`), the external tools released to the project or profile (`sessionMcp`), the permission requests (`ASK_FIRST`, `answerPermission`, and `explainCommand`, which says in plain words what each one does, where, whether it can be undone and its risk), the history (`data/sessions/<id>.jsonl`, `sessionHistory`) and the manager's lines (`sessionsLine`); in a window, the window (Windows Terminal or PowerShell, `openConsole`); and finding, measuring (`appSessionPids` for the turns in the app) and ending their processes. |
| `src/guard.mjs` | The guard of a live session in the app: `publishing` finds what a shell command would publish however it is written (`git -C dir push`, `bash -c "git push"`, `gh api` or a web request that changes something on GitHub, such as opening a pull request), and the file runs as Claude Code's PreToolUse hook (`guardHooks`, in `--settings`) to refuse what the owner has not allowed. Its refusals become permission requests like those of `ASK_FIRST`, whose rules only match a command's first words. |
| `src/context.mjs` | A project's Context tab (and `cli.mjs project-context`): everything each member, the team lead and the final review get, put together by the runs' own code (`promptParts` and `stepTools` in `src/runs.mjs`, the agents' `instructionParts` in `src/config.mjs`, the prompt builder's block `details`), with sources and sizes; the live sessions' first messages; the comparison with the last `.context.md` of a real step; the changes from the app, previewed (`previewChanges`) before they are saved (`saveChanges`) and recorded in `data/projects/<id>/context-history.jsonl`. A new part of a step's prompt goes in `promptParts`, with its key and source, and its title in `ui/app.js` (`contextPartTitle`). |
| `src/projects.mjs` | What a project's page in the app reads and does: the project's facts, your clone and the branch checked out there, opening the clone in File Explorer or VS Code, and the development environment (`dev_start`), run in a window of its own through `cli.mjs dev-run <project>` and stopped with everything it started. Every action takes `dryRun`. |
| `src/manager.mjs` | The conversation with the manager: the queue of messages sent while it answers (delivered together when it ends), the interruption that keeps the session, and the renewal with a summary when its context fills up. |
| `src/news.mjs` | The manager's news: the events reported where they happen (`reportEvent`), kept in `data/manager/news.json`, grouped for a minute (an `urgent` one, such as `merge_failed`, goes at once) and handed to the manager (`deliverNews` in `src/manager.mjs`) as a system message marked as not the owner's, or into its queue while it answers; `manager_updates` picks the events. A new event goes in `NEWS_EVENTS`, with its name in `ui/app.js` (`newsEvent`). The away mode (the app's button, `setAway`, `/api/away`): `away` and `back` always go; while away, the events in `HELD_WHILE_AWAY` wait in `data/state.json` and go with `back` for the manager's summary, and `src/notify.mjs` shows only the urgent Windows notifications. |
| `src/machine.mjs` | This computer: the projects' processes (the development environments started from the app included), their memory and stopping them (Windows). |
| `src/planning.mjs` | The owner's planning board (`data/plan.json`): its items, the import of the manager's old `data/manager/plan.md`, the items that follow their runs (through `onRunSaved` in `src/store.mjs`), the crew's proposals (`proposeItem`), the manager's triage (`triageItem`), the owner's decisions and order (`decideItem`, `reorderItems`), the approved items started one per project at a time (`startApproved`) and the summary for the manager. |
| `src/radar.mjs` | The project radar (`data/radar.json`): ideas for new projects, with their fundamentals, scores and sources (`addIdea`, `updateIdea`; links only http(s)), the owner's decisions (`decideIdea`: "choose" proposes an item on the planning board under the project `radar`), the app's commands (`changeRadar`, behind `/api/radar` and `cli.mjs radar`) and the manager's line (`radarLine`). |
| `src/autopilot.mjs` | The optional autopilot (`autopilot` in the settings): every minute, the projects whose queue is empty (`idleProjects`), the items triaged "now" (`candidates`), the limits (`blockInfo` for the app, `blockReason` in words: the 5-hour window, the week's pace, the quiet hours), the settings changed from the app's Usage section and the command line (`changeAutopilot`, behind `/api/autopilot`) and what the app shows (`autopilotStatus`: whether it may act now and what it did today; `drawAutopilot` in `ui/app.js`), the `idle` news that wakes the manager once per empty queue, its approval (`autopilotApprove`, behind `plan approve <n> --autopilot`), the daily report (`autopilot_report`) and the manager's line (`autopilotLine`). |
| `src/watch.mjs` | The watchdog, run apart from Chiefmate every 10 minutes by the Windows task `\Chiefmate\Watchdog` (`scripts/watch.vbs`, `cli.mjs watch`): the checks with no AI (`findProblems`, `orphansIn`), its state in `data/watch/`, the owner's notification and the manager's `watchdog` news (through `/api/watchdog`, or kept for the next start), and the rescuer (`callRescuer`, `rescuePrompt`): Claude Code, only when Chiefmate is stuck, with a closed list of safe actions (`rescueRestart`, `rescueStopOrphans`, `rescueResume`, behind `cli.mjs rescue`). A new action of the rescuer goes in that list, checking on its own what it touches. |
| `src/files.mjs`, `src/sheets.mjs` | The file viewer, read only: its roots (`viewerRoots`: the projects' working copies and your clones, the libraries, `viewer.extra_roots`), the check of every path (`checkPath`: the real path, links and junctions followed, inside a root, no protected name or place, `blockedName`, `blockedPlaces`), a relative path looked for in the project's copies, the newest winning (`projectPlaces`, `newestCopy`; `from` in the file's facts), and, when no copy has it, where it was looked for and which copy is behind its origin (`behindOrigin` in `src/workspace.mjs`), a folder's list, a run's files from its branch (`runFiles`, against `run.baseCommit`), the reading of a file as bytes, text or a table (`viewFile`) and the headers of its bytes (`rawHeaders`); CSV and XLSX with zlib, no dependency (`src/sheets.mjs`). Served by `filesRoute` in `src/server.mjs` (GET `/api/files/...`), drawn by the file viewer's section of `ui/app.js` (`openFile`, `fileLink` for the paths in texts, `runFilesHtml`, `drawProjectFiles`). |
| `src/plan.mjs` | The plan's free resets, the week's pace and the alerts (usage, memory, resets), which only warn. |
| `src/attention.mjs` | What needs the owner, in three levels (urgent, important, info), built from the requests, runs, usage, memory, resets, the board and the update (`attentionItems`), with the seen marks in `data/state.json`. What no longer needs the owner goes to the archive (`attention_archive` in `data/state.json`, `attentionArchive`, `/api/attention/archived`, the app's "Archived (N)"), with its reason: its cause ended, it was seen or a day old (info), or its pull request was merged or closed on GitHub or its branch merged in `local_clone` (`checkPullRequests`: `gh` and `git` in the background, at most every 5 minutes). The app draws every notice with one component (`attnMark` and `attnNotice` in `ui/app.js`, `.attn` and `data-level` in `ui/style.css`); a new kind of notice goes here, with its level. Urgent Windows notifications stay on screen (`notify(..., { urgent: true })`). |
| `src/usagepage.mjs` | The optional, read-only reading of the account's usage page on claude.ai, through Edge or Chrome. |
| `src/claude.mjs` | Runs Claude Code headless (`claude -p`), without the user's own configuration, and follows each action and how full the context is; interrupts a step at a safe point (once its actions under way finish) and reads a step's log for the agent's panel. |
| `src/access.mjs` | What each step may see: its folders, the permission rules that deny the rest, its MCP servers and the repository's instruction files. |
| `src/merge.mjs` | Merging a finished run's work, only with the owner's authorization (the app's **Merge** or a card's **Approve**, or the manager's `merge <id> --yes` after the owner's explicit yes): the pull request through `gh pr merge`, or the local branch into the owner's clone; then `run.merged`, the board's item done, for Chiefmate the update check, and the copies the owner reads brought up to date (`refreshCopies`: the project's reference library, `projectLibraries` in `src/workspace.mjs`, and, for a pull request, the owner's clone by a fast forward only, `fastForward`; what is left alone is said in the merge's answer, `copiesNote`, and in the `merged` news). When the owner's merge fails, the manager hears of it at once (`merge_failed`, with gh's or git's output and whether it is a conflict), queues the fix of a conflict and tells the owner in one line; the app's error says the manager was told. Discarding it on the owner's click (`discardRun`): `gh pr close`, or the local branch left unmerged; then `run.discarded`. |
| `src/decisions.mjs` | The owner's decision cards (`decisionCards`, in the state as `decisions`; `decisionCardHtml` and `drawDecisions` in `ui/app.js`, `.decision` in `ui/style.css`), built from the attention notices: a pull request or branch to merge, a triaged proposal, a question of the manager's (`addQuestion`, behind `cli.mjs ask-owner` and `/api/ask-owner`, kept in `data/manager/questions.json`). Each says what it is, what changes, the risk and the recommendation, with the project beside its number; a merge's recommendation is read from the final review's verdict after its "Recommendation:" label (`verdictRecommendation`: `recommendShort` is the verdict alone, "Approve with caveats", for the compact card). The owner's click (`decide`, behind `/api/decide`): approve (`mergeRun`, or `decideItem`), not now (the notice marked seen), discard, or an answer; each reaches the manager as `owner_decided` news. `projects.<id>.merge_by_owner: false` leaves a project's pull requests without Approve. Each card's `approval` is the level the manager gave its run (`run.level`, set by `createRun`'s `level` or `setRunLevel` in `src/runs.mjs`, behind `/api/level`), board item (`item.level`) or question (`q.level`), read by `parseLevel` in `src/util.mjs`; the app draws it (`approvalBadge`), folds level 1 apart and leaves it out of the menu's count (`managerSettles` in `ui/app.js`). |
| `src/needs.mjs` | When a step needs the owner (`needs-you`): the request, the notice, the address opened in the browser and "I did it"; a question (`--options`, `--recommend`, `--why`) always waits, and the option clicked (`finishRequest`, `requestButtons` in `ui/app.js`) is its answer. |
| `src/leads.mjs` | The projects' team leads (`projects.<id>.lead`; the member itself is built by `projectLead` in `src/config.mjs`): the project memory in `data/projects/<id>/memory.md`, read into the prompts and saved from the block the lead returns; the plan of a request (`ask`), at most `MAX_TASKS` tasks put in the run as steps; the lead's opinion for the final review; and the manager's line about each lead. |
| `src/talk.mjs` | The owner's direct talk with an agent at work, from its panel in the app: the message (an answer to the agent's open request, or an interruption at a safe point and the same session resumed with it), the record in the run (`talk`), the section of the step's report and the manager's summary. |
| `src/prompts.mjs`, `src/promptsync.mjs` | The optional prompt builder: reading the document of blocks (variables inside variables, "include with" and "requires" by names and tags, labels, ready combinations), putting a step's or a session's instructions together, the app's prompt builder screen (`composeChoice`, `builderPage`, the last choice per project), where the document comes from (`builderSettings`: a library's copy with `library_file`, else `file`) and bringing it up to date (`syncPrompts`: the library's copy and the document's last commit, through `libraryFileCommit` in `src/workspace.mjs`, or a copy from Google Docs). |
| `src/workspace.mjs` | git and the projects' working copies. `run()` stops a command at its time limit or on its `signal` together with every process it started (`taskkill /T /F` on Windows, where git's download helper would outlive it); a first copy is cloned beside its place and moved there once complete, borrowing `local_clone`'s objects. With `no_trace` (local delivery's default): the neutral branch name (`runBranch`, `freeBranch`), the search for traces of Chiefmate in the run's own work (`traces`: commits on no branch of origin, and the added lines `git blame` gives them) and the fast forward of the owner's branch (`advanceClone`). |
| `src/update.mjs` | The self-update: the check every 10 minutes (and on `update-check`), `auto_update_mode` and "update now". While an update is installed (`updating()`), the queue starts nothing and the manager no answer; the runs going on pause through `pauseLive` in `src/runs.mjs` (their step keeps its session in `step.paused` and resumes it with `updatedTurn`; a run preparing its working copy has it stopped through `l.preparing`, an `AbortController` that `prepareWorkspace` and `run()` in `src/workspace.mjs` obey, and prepares it again on resume), the app shows the runs it still waits for (`installing.waitingFor`), the manager's answer ends, and if the new version doesn't go in, everything resumes (`hooks.resume`, given by `src/cli.mjs`). |
| `src/digest.mjs` | Plain words for the owner: a run's short title and summary (`generateBrief`, from the instruction's first sentence until then), the final summary of each step and run (`parseOutcome` reads it at the top of a report; `generateOutcome` writes the run's), all through one short call to `quick_model` with no tools (`askQuick`). What an agent is doing now is `describeDoing` in `src/claude.mjs`. A run's title and summary are generated by `describeLater` in `src/runs.mjs`, for old runs too. |
| `src/store.mjs`, `src/config.mjs`, `src/i18n.mjs`, `src/notify.mjs`, `src/util.mjs`, `src/cli.mjs` | Records, settings and the crew, translations, Windows notifications, helpers and the command line. |
| `ui/` | The app: plain HTML, CSS and JavaScript modules, with no build step. `faces.js` draws the crew. The menu's sections (`navSections` in `ui/app.js`) each carry a mark with their count, in the level's color, an urgent one pulsing (`data-level` on the link; still with reduced motion); the decision cards have their own section, Decisions (`#decisions`), and their notices count there only (`cardedIds`). The band at the top (`drawAlerts`) leaves out the notices the page lists itself and, on the Conversation, all but its own; a permission asked shows there without its facts (`attnNotice(i, true)`). Focus mode (`setFocusMode`, `html.chat-focus` at the end of `ui/style.css`, kept in `localStorage`) leaves only the conversation and one thin line (`drawFocusBar`) with the sections that need the owner. Phones (600 px or less) have their own layout at the end of `ui/style.css`: the bottom bar (Conversation, Decisions, Operations and Projects; the links with `nav-extra` go under **More**, `setNavMore` in `ui/app.js`), the app's height from `--app-h` (the visible area, above the keyboard) and the conversations' from `--view-h`, and, while the on-screen keyboard is open over a field (the visible area well shorter than the screen, `keyboardOpen` in `ui/app.js`), `html.typing`, plus `html.typing-chat` when the field is in a conversation (only its messages and field stay; `fitField` grows the field). There, the decision cards use the buttons' short labels (`.short`). On phones the text is 15 px (nothing under 11 px), a section's header is its title alone (the description is for wider screens), the band is one row and carries no info notices (they stay in each section's list, and off the bottom bar), and the conversations run from edge to edge; `npm run smoke` checks the type, the headers and the band. A grid column that holds text is `minmax(0, 1fr)`, never `1fr`: anything wider than the screen makes the phone zoom the whole app out. |
| `agents/` | The crew's default instructions. |
| `config/example.json` | The settings template. Each installation's `config/chiefmate.json` is private and never in git. |
| `scripts/` | Installation on Windows, launchers, `check.mjs` and `smoke.mjs`. |

## Rules

1. **English everywhere**: code, comments, documentation and commit messages.
2. **Every text the user sees is translated.** On the server it goes through `t()` (`src/i18n.mjs`); in the app, through `t()` (`ui/i18n.js`) or a `data-t` attribute in `ui/index.html`. Write `t()` with a plain quoted string, and add each new text to `ui/locales/pt-BR.json` with a Brazilian Portuguese translation. `npm run check` fails when one is missing.
3. **No dependencies.** Node.js built-ins and plain browser APIs only. No build step. The one exception is optional: `playwright-core`, loaded on demand for the prompt builder's copy (and the sign-in browser), with a clear message when it is missing. Nothing else may need it.
4. **Keep the settings compatible.** Installations update themselves, and their settings are not in this repository. A new setting needs a default in the code. Never rename or remove a setting without migrating it automatically.
5. **Security is not negotiable.** Don't weaken any of these:
   - the server listens on 127.0.0.1 only, the remote access's listener too;
   - the Host, Origin and `x-chiefmate` checks on every command, and on the remote access the tailnet name, the Origin and the allowed Tailscale login on every request;
   - the safety headers on every answer (`SAFE_HEADERS` in `src/server.mjs`);
   - the file viewer: read only, its roots and protected names and places, the real path checked (`checkPath` in `src/files.mjs`), and its answers' headers (`rawHeaders`: no cache, no use by other sites, nothing run in the app's context);
   - the tools agents may never use (`ALWAYS_DISALLOWED` in `src/runs.mjs`, and the conversation's list in `src/manager.mjs`);
   - the removal of the Claude session's variables in `src/claude.mjs`, and the flags that keep the user's own Claude Code configuration out of every step and every live Claude Code session (`--setting-sources project,local`, `claudeMdExcludes`, `--strict-mcp-config`; `sessionArgs` in `src/sessions.mjs` for a window, `claudeArgs` through `runClaude` for a session in the app);
   - what each step may see (`src/access.mjs`): only its project, its own documentation folder and the libraries it lists;
   - the watchdog's rescuer: only its closed list of actions (`src/watch.mjs`), no tool that changes files, and the `rescue` actions refused inside a step or the manager's answer;
   - the rule that only Chiefmate pushes branches and opens pull requests, and merges them only with the owner's authorization (`src/merge.mjs`; `cli.mjs merge` refuses to run inside a step).

   Any change in these places must be explained in the pull request, under a "Security" heading.
6. **The look**: dark and formal, with thin lines, square corners and brass as the only accent color. No rounded, generic web look. The crew's faces are line art.
7. **Windows scripts** (`.ps1`, `.vbs`) are ASCII-only, with CRLF line endings. A launcher starts Chiefmate with `node src/cli.mjs server --log` and never redirects its output (`>> dataserver.log`): cmd keeps a redirected file locked while Chiefmate runs, and the self-update could not restart it.
8. **One improvement at a time**, small and complete. Update the README and this playbook when your change makes them outdated.

## Where the work comes from

1. The open issues of this repository (`gh issue list --state open`), oldest first, unless one is labeled `priority`.
2. If there are none: what you can see is weak. A bug, an unclear text, a confusing screen, a missing piece of documentation.

Pick one thing and finish it. Say in your report which issue it closes, if any.

## How to test

- `npm run check`: the syntax of every script, and the translations.
- `npm test`: the unit tests (`scripts/unit.mjs`, `node:test`), with made-up files in a temporary folder.
- `npm run smoke`: starts a temporary Chiefmate on a spare port, with records of its own in a temporary folder, and checks that the app and the API answer. Never let it send a real message to the manager: that starts Claude Code. Never let it open a window, a browser or a program on the owner's computer either: test what opens things with `dryRun` (or `--dry-run`) and made-up settings.
- For a change in the app's look, describe in your report what changed and where, so it can be checked without reading code.

## The pull request

Chiefmate opens it. Its text is in English:
- what changed for the people who use Chiefmate;
- the files;
- how it was tested;
- when relevant, a "Security" section.
